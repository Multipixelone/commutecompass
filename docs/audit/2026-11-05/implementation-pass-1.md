## WT01 implementation safeguards

The scoped persistence review strengthened the initial audit acceptance cases:

- Retirement must remain durable if a replacement has already been claimed or cancelled; checking only for a currently pending replacement is insufficient. Retired leave history cannot suppress a new generation's prep reminder.
- Confirmed-absent events must lose their current stored plan as well as reminders, so poll cannot recreate them. Cleanup remains scoped to the logical day; transient planning failures retain the last known-good state.
- Failed alert announcements need persisted intent independent of the saved replan: the next poll may have no new route delta. The implementation uses alert-specific bounded intent state, not a general task/outbox framework. Local leases fence state updates; they do not promise exactly-once remote delivery across crashes.
- Day selection uses aware instants and an exclusive `[NYC 02:00, next NYC 02:00)` interval, including both fall-back folds. Equal-instant ordering uses event ID for plans and ping ID for pings.

- Morning reconciliation/removal must compare the expected plan captured before external work, rejecting stale writes rather than overwriting a concurrent poll. An unchanged still-eligible due retry survives a deadline becoming past; genuinely obsolete schedules retire, and consumed reminders do not become fresh ones.
- Retry counters belong to a scheduled generation: an identical deadline preserves its ID, attempts and consumed state; a genuinely changed deadline may create a fresh generation with zero attempts, while the retired prior row retains its original timestamps and counters.
- Schema changes must be additive, versioned and idempotent, preserving historical timestamps and attempt counts. Legacy processing rows are not backfilled as delivered. Cancellation/event expiry stops stale announcement retries; mixed-version writers during upgrade are unsupported. Calendar completeness defects remain for WT02.

These safeguards are implementation contracts, not claims of completed validation.
